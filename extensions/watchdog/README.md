Reports failed runs to their subagent owner or @ultimate, and reminds @ultimate about open branches idle for more than 30 minutes (two hours while the branch waits on a reply it asked for).

Provider errors classified as temporary by Pi and Claude Code relay responses that ended incomplete with status 200 or unknown are continued twice, 60 seconds apart (`RETRIES` in `server.ts`), so a provider that fails intermittently for hours outlives a single wait; a spent account — a quota, a usage limit, an empty balance, a rate limit Pi already retried (`outOfQuota` in `lib/rate-limit.ts`) — and a model the provider does not serve get one continuation, because one step onto another model is what can help. The models extension marks the provider that refused, so such a continuation runs on another model when one has a login (see `extensions/models/README.md`), and the refusal after its last continuation is reported: the third consecutive failure still escalates. A broken login (“not logged in”, a failed OAuth refresh, `invalid_grant`) and a refusal no retry fixes (a billing notice, a `402`) are reported at once with a hint to log in again that names the provider (`diagnose` in `server.ts`). If someone has resumed the conversation and it is busy at that deadline, watchdog leaves it alone. `subagent stop` cancels that child's pending watchdog task and withdraws any queued retry input, using the stop handler's captured identities so replay leaves later work alone. Persistent and non-temporary errors become a `watchdog.failure` card with the conversation, title, error, last tool step and any login hint; reporting a subagent's failure marks its parent's `failed` action for it `given-up`. @ultimate's own failure raises a notice instead. User Stops are ignored; reply-expecting Messages inputs already have a failure reply and are excluded.

A root receipt and background task are created atomically for each failed generation; retry/report submissions use stable request IDs. On open, missed failures are scanned above the stored high-water mark, never advancing past unfinished work. Fresh installation marks existing tasks as historical and reports none of them.

The `watchdog.idle` input note is only for @ultimate and only when its set of branch IDs changes. It excludes concluded, running (including owned children), recently active, user-question-waiting and lander-queued branches. A branch counts as idle after 30 minutes, since a coordinator that ended its run with nothing to wake it may have stalled; one with an open reply-expected message to another conversation gets two hours. It lists at most ten, and clears with “No branches are idle.” It never changes the system prompt.

Watchdog keeps the last 20 reported failures (`watchdog.reported` on the root, written with each report, including @ultimate's own) and serves them through `WatchdogApi.failures(since)`, newest first; the `status` extension reports them.
